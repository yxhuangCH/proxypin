# 10 - 画中画（PiP）悬浮窗实施

> 状态：已实现并真机验收（Plan B：原生只读状态窗；Plan A 复用 Flutter 渲染面经 POC 证伪）
> 日期：2026-10-20（POC + 一、二期完成于 2026-10-21）
> 分支：`feature/add_floating_window`
> 目标环境：HarmonyOS 6.1 / API 24 起（验收于 Mate 80 Pro，HarmonyOS 7.0 / API 26）
> 关联文档：[06-鸿蒙平台适配要点.md](06-鸿蒙平台适配要点.md)、[09-应用白名单与VPN路线实施.md](09-应用白名单与VPN路线实施.md)

## 1. 背景与缺口

Android 版在 VPN 运行中退后台时进入系统画中画（PiP）小窗，小窗内显示最近请求 URL，系统控制面板提供「启停 VPN / 清理会话」按钮。

当前鸿蒙版缺失该能力，原因是三重叠加：

1. **Dart 门禁拦截**：`lib/ui/mobile/mobile.dart:301` 硬编码 `!Platforms.isAndroid()`，ohos 直接返回 false，连 channel 都不会调用；
2. **原生未实现**：`ohos/entry/src/main/ets/plugins/` 仅有 Share/Scan/KeepAlive/Vpn/ProcessInfo 五个插件，无 `com.proxy/pictureInPicture` 实现；
3. **无生命周期桥接**：Android 依赖 `MainActivity.onUserLeaveHint()` 桥接退后台事件（`android/.../plugin/AppLifecyclePlugin.kt`），ohos 无等价回调。

## 2. 平台能力核实

### 2.1 `@ohos.PiPWindow`

核实依据：本机 SDK 24 `openharmony/ets/api/@ohos.PiPWindow.d.ts` 与华为官方文档。

| 能力 | 事实 |
|---|---|
| 设备支持 | Phone API 12+、Tablet 12+、PC/2in1 13+ |
| 权限 | **无需任何权限声明** |
| 能力判断 | `canIUse('SystemCapability.Window.SessionManager')`、`PiPWindow.isPiPEnabled()` |
| 创建控制器 | `PiPWindow.create(config[, contentNode: typeNode.XComponent])`（contentNode 重载 API 12+） |
| 进入 / 退出 | `controller.startPiP()` / `controller.stopPiP()` |
| 退后台自动进入 | `controller.setAutoStartEnabled(true)`（API 11+），系统在 Home 手势后自动拉起 |
| 生命周期 | `on('stateChange')`：`STARTED`、`ABOUT_TO_RESTORE`、`STOPPED`、`ERROR` 等 |
| 系统开关 | `controller.getPiPSettingSwitch()`（API 20+），用户可在系统设置关闭画中画 |
| 内容载体 | 必须是 `XComponentType.SURFACE` 的 XComponent；TEXTURE 会黑屏 |
| 控制面板 | `controlGroups` 仅支持预定义视频控件（播放/通话类），**不可自定义按钮** |
| 自定义 UI | `customUIController`（NodeController）叠加在内容之上，官方标注**不可交互** |
| manifest | Stage 模型无需配置；`supportPipMode` 是 FA 旧模型字段 |

### 2.2 flutter_ohos 嵌入层已自带 PiP 支持

解包 `ohos/har/flutter.har` 核实：

- `FlutterPage.ets:49` 的渲染载体是 `XComponent({ id: viewId, type: XComponentType.SURFACE, libraryname: 'flutter' })`，**恰好满足 PiP 对 SURFACE 的要求**；
- `viewId`（`oh_flutter_N`）由 `FlutterAbility.onWindowStageCreate` 写入 LocalStorage，可通过 `FlutterManager.getInstance().getFlutterViewList()` 获取；
- `PiPVisibilityBridge.ets` 轮询 `window.getGlobalWindowMode()` 的 `GlobalWindowMode.PIP` 位；
- `FlutterEngine.ets:100-102` 注册监听并调用 `flutterNapi.setPipVisible()` → 原生 `nativeSetPipVisible`，说明引擎被设计为 **PiP 期间持续渲染、不因窗口不可见而暂停**。

结论：嵌入层为 PiP 持续渲染预留了链路，**但 POC 证明这不足以支撑"复用 Flutter 渲染面"**（见 §7）。

### 2.3 能力边界（与 Android 的硬差异）

1. 鸿蒙 PiP 控制面板只能使用预定义视频控件，**无法添加"停止 VPN / 清理会话"按钮**；
2. `customUIController` 不可交互，不能作为按钮载体；
3. 自动进入受系统设置开关约束，用户关闭后系统静默不进入；
4. 全局悬浮窗（`TYPE_FLOAT` + `SYSTEM_FLOAT_WINDOW`）仅 PC/2in1 且需 AGC 审批，手机不可用；
5. HarmonyOS 7.0 的闪控球/闪控窗（`FLOAT_VIEW`）需 AGC 审批且限直播/金融盯盘场景，当前 API 24 环境不可用。

## 3. 方案选型

| 方案 | 描述 | 结论 |
|---|---|---|
| **A. 复用 Flutter 渲染面** | 将 Flutter 的 SURFACE XComponent 作为 PiP 内容，小窗显示现有 `PictureInPictureWindow` 路由（请求 URL 列表） | **POC 证伪**（见 §7）：小窗白屏，stateChange 停在 ABOUT_TO_START |
| **B. 原生 ArkUI 状态窗** | `typeNode` 建自有 XComponent + `customUIController`，原生绘制最近 URL（只读） | **采用**，真机全项验收通过 |
| C. 通知栏控制 | 长时任务通知上添加 WantAgent 动作按钮 | 兜底，未启用 |

已确认的产品决策：

- 小窗内容：~~复用 Flutter 渲染面~~（POC 证伪）→ 原生只读覆盖层，展示最近 12 条请求 URL；
- 触发方式：自动（Home 退后台）+ 手动（返回键 / 悬浮图标）；
- 控制能力：接受只读小窗，回大屏操作；不做通知栏按钮、不映射播放控件；
- 鸿蒙 `pipEnabled` 默认开启。

## 4. 总体设计

```
                 ┌──────────────────────────────┐
                 │ Dart: MobileApp / pip.dart   │
                 └───────┬──────────┬─────┬─────┘
       setEnabled(bool)  │          │     │ addData(最近请求 URL)
                         ▼          ▼     ▼
              ┌──────────────────────────────────┐
              │ ProxyPinPipPlugin (ArkTS)        │
              │  reconcile(): enabled && vpnRunning
              │   ├─ 离屏自建 SURFACE XComponent  │← 内容占位（不渲染）
              │   ├─ customUIController 覆盖层    │← Column+Text 渲染最近 URL
              │   ├─ PiPWindow.create(config,node)│
              │   └─ setAutoStartEnabled(true)    │
              │  stateChange → appLifecycle 通道  │
              └───────▲──────────────┬───────────┘
                      │              │
        VPN 状态通知   │              │ STARTED / ABOUT_TO_RESTORE
              ┌───────┴───────┐      ▼
              │ProxyPinVpnPlugin│   Dart: 同步 PictureInPicture.inPip
              └───────────────┘
```

核心流程：

1. **arm（武装）**：`pipEnabled && VPN 运行` 时创建 PiP 控制器并 `setAutoStartEnabled(true)`；
2. **自动进入**：用户按 Home，系统拉起 PiP，`stateChange: STARTED (reason=autoStart)`；
3. **手动进入**：返回键 → Dart 调用 `enterPictureInPictureMode` → `startPiP()`；
4. **内容刷新**：抓包产生新请求 → Dart `addData(url)` → 原生环形缓冲（12 行）→ 若在小窗中则 `overlay.rebuild()`；
5. **恢复/关闭**：`ABOUT_TO_RESTORE` / `STOPPED` → 出站 `onPictureInPictureModeChanged(false)`；
6. **disarm**：VPN 停止或用户关闭设置 → `stopPiP()` 并销毁控制器引用。

## 5. 原生实现设计

### 5.1 新增 `ohos/entry/src/main/ets/plugins/ProxyPinPipPlugin.ets`

参照 `ProxyPinVpnPlugin.ets` 的 `FlutterPlugin + MethodCallHandler` 范式，构造注入 `common.UIAbilityContext`。

**Channel：**

- 入站：`com.proxy/pictureInPicture`（与 `lib/native/pip.dart` 协议一致）
- 出站：`com.proxy/appLifecycle`，调用 `onPictureInPictureModeChanged(bool)`（复用现有 Dart 处理链 `lib/native/app_lifecycle.dart`）

**方法（实际实现）：**

| 方法 | 行为 |
|---|---|
| `enterPictureInPictureMode` | `isPiPEnabled()` → `ensureController()` → `startPiP()`；返回 bool（忽略 host/port/appList 参数） |
| `exitPictureInPictureMode` | `stopPiP()` |
| `setEnabled({enabled})` | 更新 `enabled` 后按 `enabled && vpnRunning` 决定 arm/disarm |
| `addData` | 追加一行最近请求到环形缓冲（12 行），小窗中即时刷新覆盖层 |

**内容载体（Plan B）：**

```typescript
const windowUIContext = this.uiContext.windowStage.getMainWindowSync().getUIContext();
this.xcompController = new XComponentController();
const contentNode = typeNode.createNode(windowUIContext, 'XComponent',
  { type: XComponentType.SURFACE, controller: this.xcompController } as XComponentOptions);
const config: PiPWindow.PiPConfiguration = {
  context: this.uiContext,
  componentController: this.xcompController,
  contentWidth: 1080,
  contentHeight: 640,
  customUIController: this.overlay,   // PipOverlayController：Column + Text 列表
};
const controller = await PiPWindow.create(config, contentNode);
```

要点：

- XComponent 由 `typeNode.createNode` **离屏创建**（从未挂到主窗口树），PiP 才能接管其 surface；
- `customUIController` 是覆盖在内容之上的自定义布局（官方标注不可交互），用 `NodeController.rebuild()` 驱动刷新；
- 不设置 `templateType` / `controlGroups`，避免视频模板校验。

**状态映射：**

| PiPState | 处理 |
|---|---|
| `STARTED` | `inPip = true`，出站 `onPictureInPictureModeChanged(true)` |
| `ABOUT_TO_RESTORE` / `STOPPED` | 若 `inPip` 则置 false 并出站 false（去重） |
| `ABOUT_TO_START` / `ABOUT_TO_STOP` / `ERROR` | hilog |

**容错：**

- `isPiPEnabled()` 为 false、系统开关关闭（`getPiPSettingSwitch()`，API 20+）→ 返回 false，不进入；
- `401`（参数/控制器不合法）、`801`（设备不支持）、`1300012~1300015` → `result.success(false)` + hilog，不崩溃；
- `onDetachedFromEngine` 中 `off('stateChange')`、`stopPiP()`、置空。

### 5.2 `ProxyPinVpnPlugin.ets` 联动

- setter 注入 `ProxyPinPipPlugin` 引用（`setPipPlugin`）；
- `startVpn` / `stopVpn` 成功回调中调用 `pipPlugin.onVpnStateChanged(true/false)`；
- `isRunning` 查询时同步初始 VPN 状态（冷启动 arm 的触发源）；
- VPN 状态作为 arm/disarm 的唯一触发源：VPN 停止立即退出小窗。

### 5.3 `EntryAbility.ets` 注册

```typescript
const pipPlugin = new ProxyPinPipPlugin(this.context);
const vpnPlugin = new ProxyPinVpnPlugin(this.context);
vpnPlugin.setPipPlugin(pipPlugin);
flutterEngine.getPlugins()?.add(vpnPlugin);
flutterEngine.getPlugins()?.add(pipPlugin);
```

### 5.4 `module.json5`

预期无需改动：PiP 无权限要求，Stage 模型无 `supportPipMode` 配置。若 POC 出现 `1300013` 创建失败，再排查能力声明并回写本文档。

## 7. POC 结论（2026-10-21 真机，HarmonyOS 7.0 / API 26）

原定的 5 项判据验证结果：

| # | 判据 | 结果 |
|---|---|---|
| 1 | `PiPWindow.create(config, node)` 接受声明式 Flutter XComponent + 占位控制器？ | **是**（不报 401），但无意义——见 #2 |
| 2 | `startPiP()` 迁移 Flutter surface 后持续渲染？ | **否**。小窗创建成功但**白屏**，`stateChange` 停在 `ABOUT_TO_START(1)` 永不进入 `STARTED(2)`，主窗口画面不受影响。根因：Flutter 的 XComponent 由引擎直管 surface（`libraryname: 'flutter'`，无应用侧 XComponentController），且节点已挂在主窗口树上，PiP 无法对其重挂载/接管 surface |
| 3 | `setAutoStartEnabled(true)` 自动进入 + stateChange？ | **是**（Plan B 下验证）：Home 手势后自动拉起，`reason=autoStart`，`STARTED → ABOUT_TO_RESTORE/STOPPED` 映射正确 |
| 4 | `PiPVisibilityBridge` 检测 PIP 模式，引擎不暂停？ | **是**：日志可见 `GpuReclaim: PiP visible no -> yes`，引擎在 PiP 期间保持渲染通道 |
| 5 | 恢复大屏无黑屏/卡死？ | **是**（Plan B）：双击/恢复按钮回大屏无黑屏 |

**结论：Plan A（复用 Flutter 渲染面）证伪，启用 Plan B（原生只读状态窗）。**

Plan B 验证记录：

- 手动 Back → `startPiP()` 立即 `STARTED`，小窗显示最近请求 URL 列表；
- Home 自动拉起（`reason=autoStart`）；
- 退后台期间持续抓包，`addData` 实时刷新小窗文本（覆盖层 `rebuild()` 生效）；
- 恢复按钮回大屏无黑屏；小窗 X 关闭后应用留在后台、VPN 不断；
- 冷启动 VPN 已在运行 → `isRunning` 查询同步 `onVpnStateChanged(true)` → 自动 arm（日志 `pip controller created`）；
- FAB 停止 VPN → `onVpnStateChanged(false)` → disarm。

已知限制（接受）：

- 控制面板含一个无意义的暂停按钮（系统预定义视频控件，无法移除/自定义）；
- 手动 `startPiP()` 时主窗口仍与小窗并存（系统自动拉起则无此现象）；
- 无请求时小窗为空白覆盖层（首条请求到达后才有内容）。

## 10. 与 Android 差异

| 能力 | Android | HarmonyOS（本方案） |
|---|---|---|
| 进入方式 | Home / 返回键 / 图标 | Home 自动拉起 / 返回键手动进入 |
| 小窗内容 | Flutter `PictureInPictureWindow` | 原生覆盖层（Column+Text），最近 12 条请求 URL |
| 控制按钮 | RemoteAction：停止 VPN / 清理会话 | **无**，只读小窗（面板仅系统预定义控件） |
| 保活依赖 | VPN 前台服务 | dataTransfer 长时任务（见 06 文档 §3） |
| 系统开关 | 无独立开关 | 系统设置可关闭画中画，`isPiPEnabled()` 检测降级 |

## 11. 风险

| 风险 | 等级 | 对策 | 状态 |
|---|---|---|---|
| 占位 `XComponentController` 被拒 / FrameNode 类型不符 | 高 | POC 门禁；备选自建 XComponent 提供 controller；失败转方案 B | 已规避（Plan B 不依赖节点复用） |
| surface 迁移触发 `onDestroy` 导致 Flutter 停止渲染 | 高 | POC 验证；失败则节点复用路线作废 | 已证实（白屏），Plan B 落地 |
| 鸿蒙 PiP 面向视频场景，应用市场审核可能质疑 | 中 | 保留方案 C；准备场景说明（代理状态实时展示） | 待上架时评估 |
| 系统画中画开关关闭导致自动进入失效 | 中 | `isPiPEnabled()` 检测，`success(false)` 优雅降级 | 已实现 |
| 控制能力弱于 Android | 低 | 已确认接受，文档标注差异 | 已接受 |
| Ability 重建后控制器丢失 | 低 | `resumed` 时重新 `setEnabled` arm | 已实现（launch.dart） |
