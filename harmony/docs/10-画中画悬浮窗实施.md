# 10 - 画中画（PiP）悬浮窗实施

> 状态：方案设计完成，待 PoC 验证
> 日期：2026-10-20
> 分支：`feature/add_floating_window`
> 目标环境：HarmonyOS 6.1 / API 24（Mate 80 Pro 实机）
> 关联文档：[06-鸿蒙平台适配要点.md](06-鸿蒙平台适配要点.md)、[09-应用白名单与VPN路线实施.md](09-应用白名单与VPN路线实施.md)

## 1. 背景与缺口

Android 版在 VPN 运行中退后台时进入系统画中画（PiP）小窗，小窗内显示最近请求 URL，系统控制面板提供「启停 VPN / 清理会话」按钮。

当前鸿蒙版缺失该能力，原因是三重叠加：

1. **Dart 门禁拦截**：`lib/ui/mobile/mobile.dart:301` 硬编码 `!Platforms.isAndroid()`，ohos 直接返回 false，连 channel 都不会调用；
2. **原生未实现**：`ohos/entry/src/main/ets/plugins/` 仅有 Share/Scan/KeepAlive/Vpn/ProcessInfo 五个插件，无 `com.proxy/pictureInPicture` 实现；
3. **无生命周期桥接**：Android 依赖 `MainActivity.onUserLeaveHint()` 桥接退后台事件（`android/.../plugin/AppLifecyclePlugin.kt`），ohos 无等价回调。

## 2. 平台能力核实

### 2.1 `@ohos.PiPWindow`

核实依据：本机 SDK 24 `openharmony/ets/api/@ohos.PiPWindow.d.ts` 与华为官方文档。

| 能力 | 事实 |
|---|---|
| 设备支持 | Phone API 12+、Tablet 12+、PC/2in1 13+ |
| 权限 | **无需任何权限声明** |
| 能力判断 | `canIUse('SystemCapability.Window.SessionManager')`、`PiPWindow.isPiPEnabled()` |
| 创建控制器 | `PiPWindow.create(config[, contentNode: typeNode.XComponent])`（contentNode 重载 API 12+） |
| 进入 / 退出 | `controller.startPiP()` / `controller.stopPiP()` |
| 退后台自动进入 | `controller.setAutoStartEnabled(true)`（API 11+），系统在 Home 手势后自动拉起 |
| 生命周期 | `on('stateChange')`：`STARTED`、`ABOUT_TO_RESTORE`、`STOPPED`、`ERROR` 等 |
| 系统开关 | `controller.getPiPSettingSwitch()`（API 20+），用户可在系统设置关闭画中画 |
| 内容载体 | 必须是 `XComponentType.SURFACE` 的 XComponent；TEXTURE 会黑屏 |
| 控制面板 | `controlGroups` 仅支持预定义视频控件（播放/通话类），**不可自定义按钮** |
| 自定义 UI | `customUIController`（NodeController）叠加在内容之上，官方标注**不可交互** |
| manifest | Stage 模型无需配置；`supportPipMode` 是 FA 旧模型字段 |

### 2.2 flutter_ohos 嵌入层已自带 PiP 支持

解包 `ohos/har/flutter.har` 核实：

- `FlutterPage.ets:49` 的渲染载体是 `XComponent({ id: viewId, type: XComponentType.SURFACE, libraryname: 'flutter' })`，**恰好满足 PiP 对 SURFACE 的要求**；
- `viewId`（`oh_flutter_N`）由 `FlutterAbility.onWindowStageCreate` 写入 LocalStorage，可通过 `FlutterManager.getInstance().getFlutterViewList()` 获取；
- `PiPVisibilityBridge.ets` 轮询 `window.getGlobalWindowMode()` 的 `GlobalWindowMode.PIP` 位；
- `FlutterEngine.ets:100-102` 注册监听并调用 `flutterNapi.setPipVisible()` → 原生 `nativeSetPipVisible`，说明引擎被设计为 **PiP 期间持续渲染、不因窗口不可见而暂停**。

结论：**复用 Flutter 渲染面作为 PiP 内容是嵌入层已预留的路线**，不需要修改 har。

### 2.3 能力边界（与 Android 的硬差异）

1. 鸿蒙 PiP 控制面板只能使用预定义视频控件，**无法添加"停止 VPN / 清理会话"按钮**；
2. `customUIController` 不可交互，不能作为按钮载体；
3. 自动进入受系统设置开关约束，用户关闭后系统静默不进入；
4. 全局悬浮窗（`TYPE_FLOAT` + `SYSTEM_FLOAT_WINDOW`）仅 PC/2in1 且需 AGC 审批，手机不可用；
5. HarmonyOS 7.0 的闪控球/闪控窗（`FLOAT_VIEW`）需 AGC 审批且限直播/金融盯盘场景，当前 API 24 环境不可用。

## 3. 方案选型

| 方案 | 描述 | 结论 |
|---|---|---|
| **A. 复用 Flutter 渲染面** | 将 Flutter 的 SURFACE XComponent 作为 PiP 内容，小窗显示现有 `PictureInPictureWindow` 路由（请求 URL 列表） | **采用**，体验最接近 Android，且嵌入层已支持 |
| B. 原生 ArkUI 状态窗 | `typeNode` 建自有 XComponent + `customUIController`，原生绘制状态/最近 URL（只读） | 备选，仅当 A 的 POC 失败时启用 |
| C. 通知栏控制 | 长时任务通知上添加 WantAgent 动作按钮 | 兜底，不提供系统小窗 |

已确认的产品决策：

- 小窗内容：复用 Flutter 渲染面，展示请求 URL 列表；
- 触发方式：自动（Home 退后台）+ 手动（返回键 / 悬浮图标）；
- 控制能力：接受只读小窗，回大屏操作；不做通知栏按钮、不映射播放控件；
- 鸿蒙 `pipEnabled` 默认开启。

## 4. 总体设计

```
                 ┌──────────────────────────────┐
                 │ Dart: MobileApp / pip.dart   │
                 └───────┬──────────────┬───────┘
       setEnabled(bool)  │              │ enterPictureInPictureMode()
                         ▼              ▼
              ┌──────────────────────────────────┐
              │ ProxyPinPipPlugin (ArkTS)        │
              │  reconcile(): enabled && vpnRunning
              │   ├─ 解析 Flutter XComponent      │
              │   ├─ PiPWindow.create(config,node)│
              │   └─ setAutoStartEnabled(true)    │
              │  stateChange → appLifecycle 通道  │
              └───────▲──────────────┬───────────┘
                      │              │
        VPN 状态通知   │              │ STARTED / ABOUT_TO_RESTORE
              ┌───────┴───────┐      ▼
              │ProxyPinVpnPlugin│   Dart: push/pop PictureInPictureWindow
              └───────────────┘
```

核心流程：

1. **arm（武装）**：`pipEnabled && VPN 运行` 时创建 PiP 控制器并 `setAutoStartEnabled(true)`；
2. **自动进入**：用户按 Home，系统拉起 PiP，`stateChange: STARTED`；
3. **手动进入**：返回键/悬浮图标 → Dart 调用 `enterPictureInPictureMode` → `startPiP()`；
4. **内容切换**：Dart 收到 `onPictureInPictureModeChanged(true)` 后 push `PictureInPictureWindow` 路由；
5. **恢复/关闭**：`ABOUT_TO_RESTORE` / `STOPPED` → Dart pop 路由，刷新 VPN 状态；
6. **disarm**：VPN 停止或用户关闭设置 → `stopPiP()` 并销毁控制器引用。

## 5. 原生实现设计

### 5.1 新增 `ohos/entry/src/main/ets/plugins/ProxyPinPipPlugin.ets`

参照 `ProxyPinVpnPlugin.ets` 的 `FlutterPlugin + MethodCallHandler` 范式，构造注入 `common.UIAbilityContext`。

**Channel：**

- 入站：`com.proxy/pictureInPicture`（与 `lib/native/pip.dart` 协议一致）
- 出站：`com.proxy/appLifecycle`，调用 `onPictureInPictureModeChanged(bool)`（复用现有 Dart 处理链 `lib/native/app_lifecycle.dart`）

**方法：**

| 方法 | 行为 |
|---|---|
| `enterPictureInPictureMode` | 确保已 arm；`startPiP()`；返回 bool（忽略 host/port/appList 参数） |
| `exitPictureInPictureMode` | `stopPiP()` |
| `setEnabled({enabled})` | 更新设置并 `reconcile()`；Dart 在启动/恢复/设置切换时调用 |
| `isSupported` | `canIUse('SystemCapability.Window.SessionManager') && PiPWindow.isPiPEnabled()` |
| `addData` | no-op（方案 A 不需要） |

**节点解析（不硬编码 `oh_flutter_0`）：**

```typescript
const viewId = FlutterManager.getInstance().getFlutterViewList().keys().next().value as string;
const uiContext = this.uiContext.windowStage.getMainWindowSync().getUIContext();
const node = uiContext.getAttachedFrameNodeById(viewId) as typeNode.XComponent;
```

节点未就绪时用 `setTimeout` 重试（约 2s 预算），失败返回 false 并记录 hilog。

**创建与启动：**

```typescript
const config: PiPWindow.PiPConfiguration = {
  context: this.uiContext,
  componentController: new XComponentController(), // POC 验证占位控制器是否被接受
  contentWidth: width,   // 取节点测量尺寸或窗口物理尺寸，保持手机纵向比例
  contentHeight: height,
};
this.controller = await PiPWindow.create(config, node);
this.controller.on('stateChange', (state, reason) => { /* 映射见下 */ });
this.controller.setAutoStartEnabled(true);
await this.controller.startPiP();
```

不设置 `templateType` / `controlGroups`，避免视频模板校验。

**状态映射：**

| PiPState | 处理 |
|---|---|
| `STARTED` | `inPip = true`，出站 `onPictureInPictureModeChanged(true)` |
| `ABOUT_TO_RESTORE` / `STOPPED` | 若 `inPip` 则置 false 并出站 false（去重） |
| `ABOUT_TO_START` / `ABOUT_TO_STOP` / `ERROR` | hilog |

**容错：**

- `isPiPEnabled()` 为 false、系统开关关闭（`getPiPSettingSwitch()`，API 20+）→ 返回 false，不进入；
- `401`（参数/控制器不合法）、`801`（设备不支持）、`1300012~1300015` → `result.success(false)` + hilog，不崩溃；
- `onDetachedFromEngine` 中 `off('stateChange')`、`stopPiP()`、置空。

### 5.2 `ProxyPinVpnPlugin.ets` 联动

- 构造函数注入 `ProxyPinPipPlugin` 引用；
- `startVpn` / `stopVpn` / `restartVpn` 成功回调中调用 `pip.onVpnStateChanged(true/false)`；
- VPN 状态作为 arm/disarm 的唯一触发源：VPN 停止立即退出小窗。

### 5.3 `EntryAbility.ets` 注册

```typescript
const pip = new ProxyPinPipPlugin(this.context);
flutterEngine.getPlugins()?.add(pip);
flutterEngine.getPlugins()?.add(new ProxyPinVpnPlugin(this.context, pip));
```

### 5.4 `module.json5`

预期无需改动：PiP 无权限要求，Stage 模型无 `supportPipMode` 配置。若 POC 出现 `1300013` 创建失败，再排查能力声明并回写本文档。

## 6. Dart 实现设计

| 文件 | 改动 |
|---|---|
| `lib/utils/platform.dart` | 新增 `supportPip() => Platform.isAndroid \|\| isOhos()` |
| `lib/native/pip.dart` | 新增 `setEnabled(bool)`、`isSupported()`（仅 ohos 调用，捕获 `MissingPluginException`）；保留 `cleanSession` 处理 |
| `lib/ui/mobile/mobile.dart` | :301 门禁改为 `!Platforms.supportPip()`；`onPictureInPictureModeChanged` 增加 `_pipRouteShowing` 守卫，防止重复 push/误 pop；同步 `PictureInPicture.inPip` |
| `lib/ui/configuration.dart` | `pipEnabled` / `pipIcon` 默认值改为 `Platforms.supportPip()`；加载兜底同步 |
| `lib/ui/mobile/setting/preference.dart` | 窗口模式设置门禁改为 `Platforms.supportPip()`；开关变更时调用 `setEnabled` |
| `lib/ui/mobile/widgets/pip.dart` | 图标逻辑可直接复用（ohos 已走 `127.0.0.1` 分支） |
| `lib/ui/launch/launch.dart` | `resumed` 时重新 `setEnabled(pipEnabled)`，应对 Ability 重建后控制器丢失 |

Android 侧行为保持不变，新增方法仅在 ohos 调用。

## 7. POC 判据与失败分支

POC 只做最小触发链路，通过后才进入完整实现。必须回答：

1. `PiPWindow.create(config, node)` 是否接受声明式创建的 Flutter XComponent + `new XComponentController()` 占位控制器？（401 即拒绝）
2. `startPiP()` 迁移 surface 是否触发 `FlutterPage` 的 `XComponent.onDestroy`（进而 `FlutterView.onSurfaceDestroyed`）？Flutter 是否持续渲染？
3. `setAutoStartEnabled(true)` 在 Home 手势后是否自动进入，`stateChange` 是否按预期触发？
4. `PiPVisibilityBridge` 是否检测到 PIP 模式（确认 `nativeSetPipVisible` 链路），引擎不暂停？
5. 恢复大屏后是否无黑屏/卡死，路由正常。

**失败分支：**

- 判据 1 失败：尝试在 `Index.ets` 放置 1x1 隐藏 XComponent 及其 controller 供 config 使用，Flutter 节点仍作 contentNode；
- 判据 1/2 仍失败：节点复用不可行，转方案 B（原生只读状态窗，需扩展 `addData` 上报）；
- 方案 B 也不可用或审核受限：转方案 C（通知栏控制）。

## 9. 验证计划

**构建：**

- `flutter analyze`
- Android `flutter build apk --debug`（PiP 回归）
- ohos `flutter build hap` / `hvigorw assembleHap` + `signing.local.json` 签名
- macOS/iOS/desktop 编译冒烟

**ohos 真机：**

1. VPN 运行 → Home 手势 → 小窗自动出现并实时刷新请求列表；
2. 返回键 / 悬浮图标 → 手动进入小窗；
3. 恢复大屏 → 路由 pop、VPN 状态刷新、代理持续运行；
4. 小窗关闭（X）→ 应用留后台、VPN 不断、重开应用无残留路由；
5. 设置关闭 PiP → 不自动进入、手动进入返回 false 不崩溃；
6. 系统设置关闭画中画 → 优雅降级；
7. VPN 停止 → 立即退出小窗并 disarm；
8. 冷启动时 VPN 已在运行 → 首次退后台可自动进入；
9. 尺寸/旋转变化无黑屏；长时任务与息屏场景下 PiP 正常。

**日志观察点：** `ProxyPinPipPlugin`、`PiP: WindowStageEvent`、`PiPVisibilityBridge`、`FlutterPage XComponent onDestroy`。

## 10. 与 Android 差异

| 能力 | Android | HarmonyOS（本方案） |
|---|---|---|
| 进入方式 | Home / 返回键 / 图标 | 相同（自动 + 手动） |
| 小窗内容 | Flutter `PictureInPictureWindow` | 相同（复用 Flutter 渲染面） |
| 控制按钮 | RemoteAction：停止 VPN / 清理会话 | **无**，只读小窗 |
| 保活依赖 | VPN 前台服务 | dataTransfer 长时任务（见 06 文档 §3） |
| 系统开关 | 无独立开关 | 系统设置可关闭画中画，需检测降级 |

## 11. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 占位 `XComponentController` 被拒 / FrameNode 类型不符 | 高 | POC 门禁；备选自建 XComponent 提供 controller；失败转方案 B |
| surface 迁移触发 `onDestroy` 导致 Flutter 停止渲染 | 高 | POC 验证；失败则节点复用路线作废 |
| 鸿蒙 PiP 面向视频场景，应用市场审核可能质疑 | 中 | 保留方案 C；准备场景说明（代理状态实时展示） |
| 系统画中画开关关闭导致自动进入失效 | 中 | `getPiPSettingSwitch()` 检测 + 设置页提示 |
| 控制能力弱于 Android | 低 | 已确认接受，文档标注差异 |
| Ability 重建后控制器丢失 | 低 | `resumed` 时重新 arm |
