# 02 - 总体架构与产品边界

## 1. 目标产品形态

鸿蒙版 ProxyPin = **运行在鸿蒙手机/平板上的局域网代理抓包调试工具**：

```
[被调试设备 iPhone/Android/PC]
        |  Wi-Fi 手动代理 手机IP:9099
        |  访问 http://proxy.pin/ssl 安装 CA 证书
        v
[鸿蒙设备 ProxyPin]
   ProxyServer (纯 Dart 内核)
   - HTTP/HTTPS/SOCKS5/WS 代理
   - TLS 中间人 (pointycastle)
   - 拦截器链: 重写/映射/拦截/断点/弱网/脚本
        |
        v
   目标服务器 (可再经 externalProxy 级联)
```

## 2. 功能可用性矩阵

| 功能 | 状态 | 说明 |
|---|---|---|
| HTTP/HTTPS 抓包（外部设备） | 可用 | TLS 中间人全在 Dart 内核 |
| WebSocket 抓包 | 可用 | |
| 请求重写 / Map Local / 拦截 / 断点 | 可用 | 拦截器链纯 Dart |
| 域名黑白名单过滤 | 可用 | |
| 弱网模拟 | 可用 | |
| 外部代理级联（externalProxy） | 可用 | 鸿蒙机可再挂上游代理 |
| 二维码互联 / 远程设备 | 可用 | 已有 `remote_device.dart`，扫码入口一期改手动输入 |
| JS 脚本扩展 | 二期补齐 | `flutter_js` 需 QuickJS 鸿蒙移植；无脚本时懒加载不触发，一期不受影响 |
| br / zstd 响应解码 | 降级可用 | `lib/network/util/compress.dart` decode 已 try-catch 兜底返回原始字节，不崩溃但 body 显示乱码；二期用 OH NDK 编译 libbrotli/libzstd 补齐 |
| 扫码互联 | 二期 | `flutter_qr_reader_plus` 无 ohos 版；一期用手动输入地址兜底 |
| 按应用过滤（App 白/黑名单） | 不支持 | 无 VPN 层，无法识别包所属进程 |
| 抓鸿蒙本机其他 App 流量 | 不支持 | 模式边界，见路线 A 专项评估 |
| 系统代理自动设置 | 不支持 | 鸿蒙无开放 API，相关代码裁剪 |

## 3. 明确不做的功能（本期范围外）

1. 鸿蒙本机 VPN 抓包（受限权限，另行专项评估）；
2. 桌面多窗口、系统托盘等桌面专属能力（代码裁剪而非移植）；
3. 程序化安装 CA 证书到鸿蒙系统（无 API）；
4. 设置系统代理（无 API）。

## 4. 客户端接入流程（与桌面版一致）

1. 鸿蒙手机打开 ProxyPin，首页显示 `IP:9099` 与二维码；
2. 被调试设备 Wi-Fi 设置手动 HTTP 代理指向该地址（或 SOCKS5）；
3. 浏览器访问 `http://proxy.pin/ssl` 下载安装 CA 证书（iOS 需在设置中开启"完全信任"）；
4. 开始抓包。

固有限制（与桌面版相同，非本方案引入）：Android 目标 App targetSdk>=24 默认不信任用户 CA；部分 App 有证书固定（SSL Pinning）。
