# 07 - 风险登记册

## 风险列表

| # | 风险 | 等级 | 影响 | 缓解措施 | 状态 |
|---|---|---|---|---|---|
| R1 | 后台保活失败：退后台/熄屏后代理服务中断 | 高 | 产品定位受限，无法做常驻抓包 | dataTransfer 长时任务 + VpnExtensionAbility（见 08/09） | **已解决**（2026-09-30 实测）：① dataTransfer 长时任务获批且生效，首页横幅「后台保活：长时任务已开启」；② VPN 模式下 `launch.dart` 补 `_applyOhosKeepAlive()` 后，强制熄屏 6 分钟 `com.network.proxy:vpn` 进程与 `vpn-tun` 存活且双向转发正常（doc09「P2 复验」）。遗留：熄屏期间**外部向 9099 发起的路线 B 请求仍不可达**（doc06 §3.3，应用网络栈被系统冻结），属系统行为，非本产品缺陷 |
| R2 | `flutter_js`/`zstandard`/`brotli` import 即加载原生库，ohos 下直接崩溃 | 中 | 一期无法编译或启动崩溃 | 条件导入 + stub 隔离 | **已解决**：`flutter_js` 无 ohos 原生库 → `Platforms.supportScript()`（ohos 返回 false）隐藏脚本入口（`bottom_navigation.dart:162,168`、`drawer.dart:168`、`toolbox.dart:69`），`script_engine.dart:103` 运行时守卫；`zstandard` 联邦插件无 ohos 实现，decode 同步抛异常被 `compress.dart` catch 降级为透传（乱码不崩）；`brotli` 0.6.0 纯 Dart 全平台可用 |
| R3 | continuousTask 长时任务申请被审核拒绝 | 中 | 后台保活无官方路径 | 退回前台定位，产品话术兜底 | **已解决**：`backgroundModes:["dataTransfer"]`（ability 级声明）+ `startBackgroundRunning(BackgroundMode.DATA_TRANSFER)` 获批，未遇拒绝码（9800005=未声明 bgMode 仅在声明位置写错时出现）；真机长时任务通知与横幅可见 |
| R4 | ohos 引擎 fork 与主依赖版本冲突（如某插件要求更高 Dart SDK） | 中 | 需降级依赖或等待社区适配 | 锁定 ohos fork，逐个验证依赖 | **已解决**：实际采用 **oh-3.41.9-dev / Flutter 3.41.10-ohos-0.0.3-beta**（高于评估时的 3.27-ohos），全部依赖编译通过、五平台构建绿，未出现 Dart SDK 冲突 |
| R5 | 开放代理安全风险：0.0.0.0 绑定 + 无鉴权 | 中 | 公共网络下被滥用 | 访问控制（IP 白名单 + 代理鉴权）+ UI 提示 | **已缓解**：`lib/network/components/access_control.dart`（`accessControlEnabled` IP 白名单 + `proxyAuthEnabled` Proxy-Authorization Basic）接入 `http_proxy_handle.dart:47`；移动/桌面端均有设置页（`lib/ui/mobile/setting/access_control.dart`）；首页横幅提示「代理对局域网所有设备开放」。默认关闭；拦截效果未单独实测 |
| R6 | `code_forge` 含原生实现导致编译失败 | 低 | 脚本/报文编辑 UI 受损 | 一期验证 | **已排除**：`code_forge` 9.10.0 纯 Dart 可用（RustLib 是 10.x 才有的 API），ohos 编译通过 |
| R7 | 社区 ohos 适配插件质量参差（file_picker 等 fork 维护频率低） | 低 | 个别功能不可用需自修 | 优先 dependency_overrides，保留自维护 fork 选项 | **已缓解**：file_picker 无 ohos 实现 → `lib/utils/file_picker_util.dart` 门面降级；flutter_toastr → `lib/ui/component/toast.dart` 走 toastification；share_plus / device_info_plus / permission_handler 无 ohos 实现 → 运行时门禁。均无崩溃 |
| R8 | 大流量代理下手机发热/耗电超预期 | 低 | 长时间抓包体验差 | 三期压测；UI 提供"仅抓指定域名"引导以降载 | 未验证（留待压测） |

## 需本次评审确认的决策点

| # | 决策点 | 选项 | 建议 |
|---|---|---|---|
| D1 | 产品形态确认 | A. 仅前台调试工具（推荐） / B. 必须支持后台常驻 | A；若选 B 则需重估路线，可能被迫走 VPN 受限权限申请 |
| D2 | 局域网访问控制方案 | A. 来源 IP 白名单 / B. 绑定网卡选择 / C. 代理鉴权（Proxy-Authorization） / D. 组合 | 建议 A+D（白名单为主，鉴权可选） |
| D3 | 一期扫码入口 | A. 隐藏仅手动输入（推荐） / B. 一期即接 Scan Kit | A，二期补扫码 |
| D4 | JS 脚本功能排期 | A. 三期随 QuickJS 移植（推荐） / B. 一期用纯 Dart JS 解释器顶替 | A；纯 Dart 解释器性能与兼容性均差 |
| D5 | 鸿蒙版分发渠道 | A. AppGallery 上架 / B. 仅内部分发侧载 | 均不阻塞开发；上架需预留审核周期 |
| D6 | 分支策略 | A. 独立长期分支 / B. 主干开发 + 条件编译（推荐） | B：平台判断收敛后共存成本低，避免分支漂移 |
| D7 | 是否并行启动 VPN 权限 ACL 申请 | A. 并行启动（推荐） / B. 待路线 B 上线后再议 | A；申请不占开发资源且周期最长，越早越好 |

## 决策回顾（2026-09-30 定稿）

- **D1 → A + 补强**：按「前台调试工具」定位推进，但 VPN 路线落地后本机抓包已具备合法后台常驻能力（R1 已解决）。
- **D2 → A+D 已实现**：IP 白名单为主、Proxy-Authorization Basic 鉴权可选（见 R5）。
- **D4 → A 已生效**：脚本入口在 ohos 上由 `Platforms.supportScript()` 门禁隐藏（见 R2）。
- **D5 → B**：不上架，现阶段以本地开发 + hdc 侧载为准（doc09 R2）。
- **D7 → 无需再议**：doc08 修正结论——三方 VPN 只需 `ohos.permission.INTERNET`（normal 权限），**不需要 MANAGE_VPN**，故不存在 ACL 申请周期问题。

## 与路线 A（VPN 抓包）的关系

经华为官方文档复核（见 [08-VPN抓包路线专项评估.md](08-VPN抓包路线专项评估.md)）：

- 技术链路完整（VpnExtensionAbility / tun fd / protect），与路线 B 共用 Dart 内核；
- ~~`MANAGE_VPN` 自 API 12 起 ACL 开放，三方应用可申请，但实际门槛高~~ **修正**：三方 VPN 只需 `ohos.permission.INTERNET`，无需 MANAGE_VPN（详见 08/09）；
- 路线 A 已于 2026-09-30 全量落地（doc09），**风险 R1（后台保活）已随 VPN 模式一并解决**。
