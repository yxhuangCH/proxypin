# 06 - 鸿蒙平台适配要点

## 1. ohos 工程搭建

1. 安装 OpenHarmony-SIG Flutter 引擎（3.27-ohos 分支），按 flutter_flutter README 配置环境变量；
2. 安装 DevEco Studio（对应 HarmonyOS 6 / API 20 SDK）；
3. 在项目根执行 `flutter create --platforms ohos .` 生成 `ohos/` 目录；
4. 配置签名（自动化签名或手动申请调试证书/Profile），真机运行验证。

已知注意点：部分机器上 `flutter create --platforms ohos` 存在历史 issue，若失败可从 ohos 模板工程拷贝 `ohos/` 目录后改包名。

## 2. 权限声明（module.json5）

| 权限 | 等级 | 用途 |
|---|---|---|
| ohos.permission.INTERNET | normal | 代理服务绑定端口、外连目标服务器（核心） |
| ohos.permission.GET_WIFI_INFO | normal | 展示本机局域网 IP、生成连接二维码 |

无需任何 restricted / ACL 权限 —— 这是本方案相对 VPN 路线的核心合规优势。

## 3. 后台保活（最大平台风险）

### 3.1 问题

HarmonyOS NEXT 应用退后台后快速挂起，socket 服务断连。无 VPN 权限则无 NetworkExtension 式合法常驻路径（iOS 版 ProxyPin 依赖 VPN 保活，此路在鸿蒙不通）。

### 3.2 候选措施（按可行性排序）

| 措施 | 说明 | 可行性 |
|---|---|---|
| 前台使用定位 | 抓包时保持 App 前台 + 屏幕常亮（wakelock 类能力） | 高，一期即实现；调试场景用户可接受 |
| continuousTask 长时任务 | 申请 dataTransfer 类型长时任务 | 中：该类型面向上传/下载场景，代理服务不完全匹配，上架审核存疑，二期实测申请 |
| 悬浮窗/画中画保持前台态 | 折叠屏/平板场景 | 中，体验折中 |
| 熄屏挂机模式 | 引导用户系统设置中允许 | 低，路径深 |

### 3.3 实测矩阵（二期已测，Mate 80 Pro / HarmonyOS 6.1 / API 24，2026-09-28）

探针：`curl -x http://<手机IP>:9099 http://proxy.pin/ssl`（`000` = 连接失败）。

受控方法：亮屏后台组用 `power-shell timeout -o 1800000` 覆盖息屏超时（排除屏幕状态干扰，测完须恢复）；对照组 = 移除 `backgroundModes` 声明的同代码 hap（系统拒绝长时任务，9800005）。

| 状态 | 开长时任务（dataTransfer） | 关长时任务（对照） |
|---|---|---|
| 前台亮屏 | 200 通 | 200 通 |
| 退后台亮屏 1/5 min | 200 通 | 200 通 |
| 退后台亮屏 22 min | 200 通 | ~22 min 起 000（应用被冻结） |
| 退后台亮屏 29 min | 200 通（全程无中断） | 000 |
| 熄屏/锁屏 ~1 min | 000 不通 | 000 不通 |
| 回到前台 | 自动恢复 200 | 同左 |

结论与说明：

1. **长时任务有效**：亮屏退后台时，未开长时任务约 22 min 被系统冻结，开启后 29 min 以上稳定不断；
2. **熄屏/锁屏仍断**：两种变体熄屏约 1 min 内均断连——监听 socket 仍在（netstat 可见），但外部 TCP 不通（ICMP ping 通、RTT ~260ms，链路侧正常），即熄屏时设备冻结了应用网络栈，dataTransfer 长时任务未能阻止。**保活边界 = 亮屏后台**，熄屏场景需用户保持屏幕常亮；
3. 未声明 `backgroundModes` 的降级链路已验证：系统拒绝长时任务（9800005 bgMode invalid），插件返回 false，UI 显示"未开启，退后台/熄屏后代理可能中断"，代理本身不受影响；
4. 早期未控屏测试中的"20 min 冻结/立即 000"均为屏幕状态伪影，以本表受控数据为准；
5. R1 风险定级更新：后台保活（亮屏）由长时任务解决；熄屏保活无解（无 VPN 权限），维持"前台调试工具"产品定位 + 「前台常亮」设置兜底。

平板无真机，差异项待测。

### 3.4 产品话术

明确定位"调试时主动打开的抓包工具"，UI 在代理运行且 App 退后台时给出"服务可能中断"提示。

## 4. 证书流程

- **服务端**：CA 由 pointycastle 纯 Dart 生成，存 App 私有目录（`path_provider`），无需鸿蒙系统配合；
- **客户端（被调试设备）**：挂代理后访问 `http://proxy.pin/ssl` 下载安装，与桌面版流程一致；
- **鸿蒙本机**：无需安装 CA（本机不是被抓包对象）；如需抓"鸿蒙本机浏览器访问"，因无系统代理 API 也不支持，属于模式边界。

## 5. 网络与安全

1. 服务绑定 `0.0.0.0` + 无鉴权 = 公共 Wi-Fi 下开放代理风险，二期增加访问控制（白名单/网卡选择/鉴权，评审决策）；
2. 建议在 UI 上持续显示当前监听地址与已连接客户端数，提升可感知性；
3. 端口号冲突处理：现有 `retryBind()`（`server.dart:154-161`）已具备重绑逻辑，保留。

## 6. UI/UX 适配清单

- 状态栏/导航条沉浸式（鸿蒙 ArkUI 边距与 Android 略有差异，Flutter 引擎已处理大部分，真机核对）；
- 字体：`lib/utils/font.dart` 的平台分支补 ohos（跟随 Android 逻辑即可）；
- 分享面板、文件管理跳转等系统交互走 ohos 适配插件；
- 平板/折叠屏：沿用现有 responsive 布局，二期核对。
