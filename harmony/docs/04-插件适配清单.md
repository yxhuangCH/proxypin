# 04 - 插件适配清单

依赖来源：`pubspec.yaml`（v1.3.1+36）。分类：A=直接裁剪（桌面专属），B=社区已有 ohos 适配，C=纯 Dart 无需处理，D=需自研/替换。

## A. 直接裁剪（桌面专属）

| 包 | 用途 | 处理 |
|---|---|---|
| window_manager | 桌面窗口管理 | 随 `lib/ui/desktop/` 裁剪 |
| screen_retriever | 屏幕信息 | 同上 |
| desktop_multi_window | 多窗口 | 同上 |
| tray_manager | 系统托盘 | 同上 |
| win32audio | Windows 音量 | 同上 |

## B. 社区已有 ohos 适配（OpenHarmony-SIG fluttertpc_* 系列）

| 包 | 用途 | 处理 |
|---|---|---|
| shared_preferences | 配置存储 | 换 `shared_preferences_ohos` 或 dependency_overrides |
| path_provider | 目录路径（`FileRead.homeDir` 依赖） | 换 ohos 适配版 |
| device_info_plus | 设备信息 | 换 ohos 适配版 |
| url_launcher | 打开链接 | 换 ohos 适配版 |
| share_plus | 分享/导出 | 换 ohos 适配版 |
| permission_handler | 权限申请 | 换 ohos 适配版 |
| file_picker | 文件选择 | 使用社区 ohos fork |
| flutter_toastr | Toast | 若无 ohos 版，替换为 `toastification`（已在依赖中，纯 Dart）统一实现 |

## C. 纯 Dart，无需处理

`flutter_localizations`、`intl`、`cupertino_icons`、`pointycastle`、`logger`、`date_format`、`get`、`qr_flutter`、`toastification`、`html`、`xml`、`archive`、`scrollable_positioned_list_nic`

## D. 需自研 / 替换

| 包 | 用途 | 问题 | 方案 | 期次 |
|---|---|---|---|---|
| proxy_manager | Android 系统代理设置 | 鸿蒙无系统代理 API | 删除调用，功能裁剪 | 一期 |
| flutter_js | JS 脚本引擎（QuickJS 原生库） | 无 ohos 构建 | 一期：依赖懒加载不触发，保留代码隔离原生初始化；三期：OH NDK 编译 QuickJS + ohos 插件壳 | 一/三期 |
| zstandard | zstd 解压（FFI 预编译库） | 无 ohos 预编译产物 | 一期：现有 try-catch 兜底降级；三期：OH NDK 编译 libzstd | 一/三期 |
| brotli | br 解压（FFI） | 同上 | 同上，编译 libbrotli | 一/三期 |
| flutter_qr_reader_plus | 相机扫码 | 无 ohos 版 | 一期：隐藏扫码入口，手动输入地址；二期：鸿蒙统一扫码（Scan Kit）ohos 插件 | 一/二期 |
| code_forge | 代码编辑器 | 待确认是否纯 Dart | 一期验证；若非纯 Dart 评估替换为纯 Dart 编辑器 | 一/三期 |
| ffi | dart:ffi 支持 | ohos 引擎支持 | 无需处理，三期原生库的加载通道 | - |

## 降级路径的关键代码事实

- `lib/network/util/compress.dart`：`brDecode`/`zstdDecode`/`gzipDecode` 均有 try-catch，异常时返回原始字节 —— 原生库缺失不会导致崩溃，仅报文不解码显示乱码；
- `lib/network/components/js/script_engine.dart`：`JavaScriptRuntimePool` 懒创建，仅当存在启用脚本时才初始化 `flutter_js` —— 无脚本场景一期完全不受原生库缺失影响；
- 一期需在 ohos 下验证：`package:flutter_js`、`package:zstandard`、`package:brotli` 的 **import 本身**不触发原生加载（若 import 即加载，则需条件导入或 stub 隔离）。

## pubspec 改造方式

1. 优先使用 `dependency_overrides` 指向 ohos 适配版，保持主依赖声明不变，便于多平台共存；
2. 桌面专属依赖保留在主 pubspec，但鸿蒙编译路径中对应 import 需通过条件导入或代码裁剪消除；
3. 无法消除 import 的包（如 `flutter_js`），采用 stub 文件 + 条件导入（`if (dart.library.io)` 不足以区分 ohos，需自建 `platform_stub` / `platform_ohos` 双实现）。
